## 1. 决策速览（四个容量结论）

> **采样规模警示（对下文每一条「容量上限」结论都成立）**：
> 本次四组数据共 **49087 拍**（主集 10671 / 扩展集 38416），
> 与「几十万~几百万 cycle」的目标相比**偏小**，且 `p4_fpu`/`p5_mdu` 等仅 1.1k/4.5k 拍 ⇒
> **高并发尾部未被充分采样**。因此下文所有「≤ X」只能作为**高水位下界的实测值**，
> 不能当作统计上界；落地前必须用**定向高压力 workload**（p4_fpu 加压、p5_mdu 加压、
> store 密集流、误判嵌套流）复验。

### 1.1 EXP-R2｜NREG 96→64 是否可行 ⇒ **可行（余量薄）**

- **max live 物理寄存器（整数）= 58 < 64**（占 NREG=96 的 60%；架构基线占 32 ⇒ 在飞目的寄存器峰值仅 **26**）。
- **max live 物理寄存器（浮点）= 43 < 64**（浮点域 NREG=64 ⇒ 余量 21；浮点域若要同步缩减需另做评估）。
- free list 最小余量：整数 38、浮点 21（派发 4 条需要 ≥4 ⇒ 未见结构性卡死）。
- **结论**：96→64 在实测数据下**不越界**，但整数域余量仅 **6** 个物理号；
  由于采样偏小（§1 警示），建议按 **64 落地 + 高压 workload 复验**，或保守取 72/80。

### 1.2 EXP-R3｜TRQ（训练 FIFO）backlog 是否可测/可缩 ⇒ **数据不可用（缺陷 D1），先修再测**

- `trq_cnt` 与「权威指针差 `(trq_w−trq_r) mod 32`」**不一致的拍数 = 44521/49087 = 90.70%**。
- 出队事件 39251 次 vs 入队条目仅 **4359** 条（相差 9.0×）⇒ 读指针持续空转、**把陈旧/未定义数据反复喂给预测器**。
- 出队拍 `trq_r ≥ 16`（`trq[0:15]` **越界读**）**19558 拍**；其中训练 PC 读出口**含未捕获位** `tpcx` **19558 拍（= 出队事件的 49.83%）**。
- 入队拍 `trq_w ≥ 16`（越界写 ⇒ 训练条目**静默丢弃**）**2106 拍 = 入队事件的 48.58%**。
- **结论**：`trq_cnt` 高水位/积压**不能**作为容量依据（数值本身是坏的）；
  可用的结构性事实：单拍分支训练入队 ≤ COMMIT_W=4（实测峰值 3），单拍分支提交突发峰值 4（直方图见 §2.2）。
  **EXP-R3 的前置条件 = 先修 D1**，然后用同一探针重测积压。

### 1.3 EXP-R4｜SQ 32→16 是否可行 ⇒ **不可行**（高水位超 16）

- **max SQ 占用 = 20（32 项口径）**，出现在锁步 `p3_memcsr`（store 密集）；
  SQ 32→16 会**溢出 4 项**，必须靠停顿补 ⇒ 直接损失 IPC。
- `stq_used` 与独立复算 `popcount(stq_v32)` 逐拍一致（失配 0 拍）⇒ 该高水位是**真实现象**，不是计数 bug。
- 副产物：**max LQ 占用 = 6**（LQ 深度 16）⇒ LQ 16→8 在实测下有余量，可作为比 SQ 更安全的面积杠杆。

### 1.4 EXP-R5｜iterative div/sqrt 是否值得 ⇒ **在 FP 密集程序上不值得（延迟敏感）**

- 浮点发射共 50 条，其中 div **2** 条 / sqrt **1** 条（合计 3 条 = 6.00%）。
- 但 **div/sqrt 迭代占满 FPU 的拍数 = 342**（= 全采样拍数的 0.70%），
  即 FPU「忙」拍数（671）的 **50.97%** 被 div/sqrt 独占。
- 逐基准看（§2.4）：div/sqrt 占 FPU 忙拍比最高的是 `ct_p16_fcsr`
  （67.06%），`p4_fpu` 为 46.15% ⇒ FP 密集负载对
  「更快/更慢的 div-sqrt 实现」**直接敏感**。
- **结论**：op-kind 分布以 add/mul/cvt/cmp 为主，div/sqrt **条数少但占用周期多**；
  因此「用更慢的 iterative 实现换面积」在这组 workload 上**会明显增加 FP 密集程序的停顿**，
  不值得用主频/延迟去换；若一定要做，必须同时给出 div/sqrt 的专项加压复验。

### 1.5 检查点压缩到 ≤4 是否可行 ⇒ **不可行**

- 前端检查点池占用峰值 **feck = 16 = CKPT_N（16，池满）**；
  **`ckpt_full` 令前端停顿的拍数 = 861**（主集 161 / 扩展集 700）。
- 分配新检查点时的池占用分布（§2.1）显示：多数为 1，但存在持续爬升到 16 的突发段。
- **结论**：实测需求峰值触及 **16**，且池满确实造成停顿 ⇒ **压缩到 ≤4 无数据支持**。
  ⚠ 口径保留：后端释放路径是「1 个/拍」（`backend_top.v:2350-2357`），
  且后端自用的 `ck_busy_q` 只有 4 bit（缺陷 D2）⇒ 16 这个峰值**部分**可能来自释放延迟
  而非真实回滚需求；需用「深误判嵌套」定向 workload 分离两者（§4.3）。

## 3. 产品 RTL 缺陷登记（本次采集**顺带暴露**；探针未改任何 RTL）

### D1（**高影响**）TRQ 训练 FIFO：`trq_cnt` 永不递减 + 指针 mod 与数组深度不匹配

**现象（实测，见 §2.2）**

1. 出队 39251 次 vs 入队 4359 条（9.0×）—— FIFO 被反复读出陈旧条目。
2. `trq_cnt` 与指针差 `(trq_w−trq_r) mod 32` 失配 44521 拍。
3. 出队拍 `trq_r ≥ 16` 越界读 19558 拍，其中训练 PC 读出口含
   **未捕获位（x）19558 拍**（探针列 `tpcx`）。
4. 入队拍 `trq_w ≥ 16` 越界写 2106 拍 ⇒ 训练条目**静默丢弃**。

**根因（代码级，冻结树 cfc0af9）**

```verilog
// rtl/back2/backend_top.v:2500-2517
if (train_valid_o) begin              // 出队
    trq_r   <= trq_r + 5'd1;
    trq_cnt <= trq_cnt - 5'd1;        // ① 先减
end
if (disp_fire_w | cmt_ok) begin       // 入队分支（派发/提交拍**总**成立）
    ...
    if (!trq_full) begin
        trq_w   <= trq_w + {3'b0, trq_acc};
        trq_cnt <= trq_cnt + {3'b0, trq_acc};   // ② 同拍后写覆盖 ⇒ trq_acc==0 时把①的 −1 抹掉
    end
end
```

`if (disp_fire_w | cmt_ok)` 只要本拍有派发**或**提交即成立，而 `trq_acc==0` 时第二条赋值
仍然执行（`+0` 覆盖了 `−1`）。**最小反例（实测 CSV 连续 3 拍，锁步 `p1_int`）**：

| row | trq_acc | trqfire | trq_cnt | trq_w | trq_r | 应有 cnt |
|---:|---:|---:|---:|---:|---:|---:|
| 11 | 1 | 0 | 0 | 0 | 0 | 0 |
| 12 | 0 | 1 | 1 | 1 | 0 | 1 |
| 13 | 0 | 1 | **1** | 1 | 1 | **0** ← 出队了却没减 |

⇒ `trq_cnt` 在**任何「出队 + 派发/提交」同拍**都丢掉那次 −1 ⇒ 长期虚高且不归零 ⇒
`train_valid_o = (trq_cnt != 0) & train_ready_i`（:2331）持续为 1 ⇒ `trq_r` 空转跑飞。

第二条独立缺陷：数组 `reg [106:0] trq [0:TRQ_D-1]`（TRQ_D=16，:2285-2286）
用 **5 bit（mod 32）** 指针索引（:2287）⇒ 一半指针值域越界。

**修复建议（供母 Agent 派编码子 Agent；本次**未**改动）**

1. 计数改为**单一无条件表达式**：`trq_cnt <= trq_cnt - deq_n + enq_n;`
   （`deq_n = train_valid_o ? 1 : 0`、`enq_n = (disp_fire_w|cmt_ok) && !trq_full ? trq_acc : 0`），
   即把减法与加法合并到**一处赋值**。
2. 指针模数与数组深度对齐：`trq[trq_w[3:0] + trq_ord]` / `trq[trq_r[3:0]]`，
   或把数组深度改为 32。
3. 修复后**必须**用本报告的同一探针重测：期望 `trq_mismatch == 0`、`tpcx == 0`、
   出队次数 ≈ 入队条数。

**影响面**：分支预测器训练数据有近半为未定义/陈旧值（`p8_int` 等长程序更明显），
属**性能**缺陷（不影响架构正确性——锁步/回归仍 PASS，故长期未被发现）。

### D2（中）后端 `ck_busy_q` 只有 4 bit 却按 0..15 索引

`reg [3:0] ck_busy_q;`（`backend_top.v:630`）却用 `ck_busy_q[snap_id_r]`（`snap_id_r` 为
4 bit，实测出现过 0..15，见 §2.1 的 `snapid`）与 `for (si2 = 0; si2 < CKPT_N=16; ...)`
（:2478-2483）访问 ⇒ id ≥4 的写入被丢弃、读取返回 x。
实测证据：本数据集 `snapid ≥ 4` 的快照 **62 拍**（id 最大 15）。
**建议**：`reg [CKPT_N-1:0] ck_busy_q;`（与 `ck_pend_q` 同宽）。
本次「活跃检查点」因此改用**前端池** `ck_valid_v` 计量（见 §0 口径表）。

### D3（口径）rename 的 `ck_val` 只在冲刷/回滚时清零 ⇒ 不是「瞬时活跃检查点数」

`rename.v` 对 `ck_val[i]` 的写在冻结树中只有三处：复位清零、`flush_all` 清零、
`restore_valid` 清单项（:640-660、:692、:733）。**没有**「分支提交即释放」路径
（释放发生在后端 `ck_pend_q`→前端池）。故 `popcount(ck_val)` 是「自上次冲刷以来
分配过」的上界，实测饱和到 16（`cki` 峰值 = 16）。
**结论**：检查点容量结论一律以 §1.5 的前端池 `feck`/`fefull` 为准。

## 4. 数据可信度：交叉验证 + 反证实验 + 遗留风险

### 4.1 独立交叉验证（脚本判定，不靠人工）

1. **探针 vs TB 自身计数**（`fpga/scratch/dyn_crosscheck_r.py`，判定锚点
   `DYN_CROSSCHECK_R: PASS`）。把探针 CSV 的 per-基准**行数**/**提交条数**与 TB 日志里
   独立维护的**拍数**/**提交条数**逐项比对。实测：
   - 行差：锁步 `2/3/3/3/3`（复位释放 +2、程序边界 +1）、`ipc_alu4w` **0**、
     core_top **14/14 全为 2** —— 全部落在预期集合内。
   - 提交差：`ipc_alu4w` **0**；锁步 `1/1/1/0/0`；core_top 13 个程序 **+2**、
     `ct_p13_sv32` **+3**（额外提交合计 4）。+2 = 两条镜像外跳板
     （`lui x5,base; jalr x0,0(x5)`）；+1 = 陷阱/维护重定向等**镜像外**提交 ——
     TB 只数 `PC ∈ 程序镜像` 的提交（`tb_core_top_2b.sv:416-420`），探针数全部
     `commit_valid_o`，这是**已知口径差**而非计数错误。
   - 既有对照：`fpga/scratch/dyn/core_top_2b.csv`（上一轮探针，旧 RTL 版本）给出的
     core_top 逐程序提交条数与本次**逐项相同**（含 `ct_p13_sv32`=483）⇒ 两次独立采集一致。
2. **`stq_used` vs `popcount(stq_v32)`**（设计内两处独立来源）：失配 **0 拍 / 49087** ⇒ SQ 占用读数可信。
3. **`fdone` vs 浮点发射条数**：全部基准相等（成对）（50 vs 50）⇒ FPU op-kind 采集成对。
4. **`fefull` vs `feck`**：分析器逐拍断言 `fefull ⇒ feck == 16`，全数据集成立
   （否则判 FAIL）⇒ 前端检查点池读数自洽。
5. **`trq_cnt` vs 指针差**：失配 44521 拍 —— **不判 FAIL**，
   因为这是**被测 RTL 的缺陷**（D1），不是采集错误；分析器只保证「如实记录」。

### 4.2 反证实验（`python3 fpga/scratch/dyn_analyze_r.py --self-test`）

| # | 注入 | 期望 | 结果 |
|---|---|---|---|
| (a) | `freei=200`（越界，破坏 live 恒等式） | 判 FAIL | 见 stdout `ok` |
| (a2) | 只把 `livei` 改 +1（破坏恒等式） | 判 FAIL | 见 stdout `ok` |
| (b) | 某字段写成 `x`（未捕获） | 判 FAIL | 见 stdout `ok` |
| (b2) | 表头列序对调 | 判 FAIL | 见 stdout `ok` |
| (c) | 某基准 free list 全置满 | `livei_max` 必须变为 32 | 见 stdout |
| (d) | 该基准 `freei` 每行 −1 | `Σlivei` 恰 +行数 | 见 stdout |

⇒ 分析器对输入缺陷**敏感**，对探针恒等式**守约**，不是「打印常数」。

### 4.3 遗留与风险

- **采样规模偏小（对每条容量结论都成立）**：全数据集 49087 拍。锁步 5 程序 7671 拍、IPC 3000 拍、core_top 14 程序 38416 拍。`p4_fpu`/`p5_mdu` 仅 1.1k/4.5k 拍 ⇒
  **高并发尾部概率未被充分采样**；所有「峰值 ≤ X」应视为**下界观测**。
  **建议**：p4_fpu 加压（长 FMA/div-sqrt 链）、p5_mdu 加压、store 密集流、
  深误判嵌套流四类定向 workload 复验。
- **TRQ 数据不可用（D1）**：积压/高水位类结论在修 D1 前**不可采信**；
  本报告只给出结构性上界（单拍入队 ≤4）。
- **检查点峰值口径**：前端池饱和到 16 可能部分来自「1 个/拍」的释放带宽
  （`backend_top.v:2350-2357`）与 D2（`ck_busy_q` 越界）⇒ 需定向实验分离。
- **锁步 TB 把 `train_ready_i` 硬接 1**（`tb_back2_lockstep.sv:369`）⇒ 锁步集的
  TRQ 出队速率比真实前端更激进；TRQ 类结论应以 `core_top_2b` 为准。
- **`stmask`/`stsize` 只在 `stv=1` 的拍有意义**（探针已按 `exe_valid & exe_is_store` 门控）。
- **未做**：写入 `mtval`/异常路径的容量采样；AMO/CMO 路径；多 harts。
