## 5. 数据可信度：独立交叉验证 + 反证实验

### 5.1 交叉验证（探针 vs TB 自身计数）

`fpga/scratch/dyn_crosscheck.py` 把探针 CSV 的 **per-基准行数 / 提交条数** 与 TB 自己
独立维护的 **per-程序拍数 / 提交条数**（从 vvp 日志提取）逐项比对，判定由脚本给出：

- **行数**：探针恒比 TB 的 `cyc` 多 **2** 行（复位释放后的 `repeat(2) @(posedge clk)`）；
  锁步 TB 在 `clear_mem`→`do_reset` 之间多 1 个 posedge（`rst_n` 仍为 1）⇒ 允许 +3。
  实测：锁步行差 = 2/3/3/3/3；ipc 行差 = 0（已剔除复位+预热 202 行）；core_top 行差 = **14/14 全为 2**。
- **提交条数**：探针数的是所有 `rst_n==1` 拍的提交链有效条数，**包含** TB 程序计数不含的
  2 条跳板（`lui x5,base; jalr x0,0(x5)`，`tb_core_top_2b.sv:396-397`、锁步 `STUB0/STUB1`）
  ⇒ core_top 提交差 = **14/14 全为 +2**；锁步提交差 = 1/0/0/0/0（+1 为边界拍，未解释差合计 1，上限 1）。
- 结论：`DYN_CROSSCHECK: PASS` —— 探针的提交计数与 TB 的独立计数在**已知口径**内逐程序一致。

### 5.2 反证实验（`python3 fpga/scratch/dyn_analyze.py --self-test`）

| # | 注入 | 期望 | 实测 |
|---|---|---|---|
| (a) | `iqf0=99`（越界） | 判 FAIL | `inj: 队列 ALU0 occupancy 越界` ⇒ FAIL ✓ |
| (b) | 某字段写成 `x`（未捕获） | 判 FAIL | `未捕获/未知值 'x'` ⇒ FAIL ✓ |
| (c) | 某基准 `iqf0` 恒置 0（ALU0 恒 full） | `full_other_free == 拍数`、`iq_full[0] == 拍数` | 445==445、445 ✓ |
| (d) | 该基准 `free` 每行 −1 | `Σoccupancy` 恰 +行数 | 161→606（+445）✓ |

⇒ 分析器对输入缺陷**敏感**、对 occupancy 恒等式**守约**，不是「打印常数」。

### 5.3 遗留与风险

- **拍数规模**：主集 10,671 拍 / 7,436 提交；扩展集 38,445 拍 / 11,914 提交。
  与 answer.md 期望的「几十万~几百万 cycle」相比偏小 —— 现有 TB 的 5 个锁步程序本身只有
  445~4,475 拍，core_top_2b 14 程序合计 38,445 拍。**结论的方向性**（峰值远低于端口/深度上界）
  裕量很大，但极端并发下的尾部概率未被充分采样，见下条。
- **`upd` 高并发采样不足**：并发 ≥2 仅出现 3 拍（主集 2 + 扩展 1），三路并发 0 拍。
  故 rare event 的绝对占比仍应视为上界估计，而非精确概率。
- **锁步边界拍**：锁步 TB 在程序切换处有 1 个 `rst_n==1` 的 posedge 被记入**下一个**基准
  （4 拍 / 7671 = 0.05%，其中提交 0 条）。core_top 无此问题。
- **`upd_csr_valid` 恒 0**：`backend_top.v:1793` 已把该口硬接 `1'b0`（B29 改为提交级现算），
  故数据组 3 的 CSR 更新并发恒为 0 —— 这是**设计事实**，不是采集缺失。
- **`iread` 是「需求」而非「物理读口」**：`iprf_re = 16'hFFFF` 恒开，物理上 16 个口每拍都读；
  本报告的 0..11 是「该拍真正被用到的源操作数个数」，即 operand collector 要满足的需求。
