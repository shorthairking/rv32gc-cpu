# 移植方案总览：软件栈、启动流程、镜像布局与 NAND 分区

> **文档定位**：RV32-GC 新项目（重启版）移植工作的**总纲**。定义软件栈分工、上板启动流程、镜像布局与分区口径。
> **参数纪律**：本文所有平台参数**引用** `docs/kb/platform-facts.md` 的台账，**不另立参数**。平台事实的引用强度标注沿用它：[RTL 实测] / [旧项目转述] / [环境实测]。

## 1. 目标与软件栈

### 1.1 总目标

在 chiplab（龙芯 FPGA 实验箱，`xc7a200tfbg676-2`）平台上完成 RV32-GC 软硬件协同，**最终从 NAND 启动 Linux 内核、驱动与根文件系统**。

### 1.2 软件栈三层

| 层 | 组件 | 特权级 | 地址翻译 | 职责 |
|---|---|---|---|---|
| M | **OpenSBI** | M | 物理地址 | 平台初始化、提供 SBI 调用、最终 `mret` 到 S 模式的下一级 |
| S | **U-Boot** | S | **关 MMU（物理地址）** | 外设驱动（NAND/MTD）、环境变量、加载并跳转内核 |
| S | **Linux** | S | **Sv32（开 MMU）** | 内核 + 驱动 + 根文件系统 |

- **为什么 Linux 必须走 S 模式 + SBI**：`la32r-Linux/arch/riscv/Kconfig` 中 `RISCV_M_MODE` 的 `default !MMU`，而 `MMU` 的 `default y` ⇒ **M 模式被自动关闭**；同时 `RISCV_SBI` 的 `depends on !RISCV_M_MODE` + `default y` ⇒ **SBI 路线自动成立**。[RTL 实测] `la32r-Linux/arch/riscv/Kconfig:126-133`
- 因此软件栈固定为 **OpenSBI(M) + U-Boot(S) + Linux(S, Sv32)**，**不再重议**。
- U-Boot 在本方案中运行于 S 模式且**不开 MMU**（物理地址 = 虚拟地址），避免在 bootloader 阶段引入页表复杂度。

### 1.3 与平台的耦合点

| 耦合点 | 口径 | 出处 |
|---|---|---|
| 复位取指地址 | **`0x1C00_0000`**（SPI XIP 窗口） | `docs/kb/platform-facts.md` §2.3、§7 |
| 无 boot ROM | 平台无硬件 ROM，DDR3 是默认从设备 | `docs/kb/platform-facts.md` §7 |
| 时钟 | 33 MHz 同域（`cpu_clk = uncore_clk`） | `docs/kb/platform-facts.md` §5 |
| NAND 基址 | `0x1FE7_8000`，DMA 门铃 `+0x40` | `docs/kb/platform-facts.md` §2.5、§4.2 |

## 2. 上板启动流程

### 2.1 阶段划分

```
复位 ──▶ [阶段A] SPI XIP 早期引导 ──▶ [阶段B] 拷入 DDR ──▶ [阶段C] OpenSBI(M)
                                                              │ mret
                                                              ▼
                                          [阶段D] U-Boot(S) ──▶ [阶段E] Linux(S, Sv32)
```

### 2.2 阶段 A：复位 → SPI XIP 早期引导

**起点**：复位后 PC = `0x1C00_0000`。

**约束（三条硬约束）**：

1. **平台没有 boot ROM** —— `soc_top.v` 无 ROM 例化，DDR3 是默认从设备、复位后内容不确定。因此**复位取指必须落在 SPI XIP 窗口**，不能落在 DDR。[RTL 实测] `docs/kb/platform-facts.md` §7
2. **只允许 PC 相对寻址** —— 早期代码位置由 SPI 窗口决定，但**不得假定任何绝对地址**；取常量、跳转一律用 `auipc + addi` / `auipc + jalr` 组合。
3. **开 MMU 前禁止跨窗口跳转** —— 在建立页表之前，**不得**从一个地址窗口跳到另一个窗口；所有控制流必须在当前窗口内保持 PC 相对。跨窗口迁移必须通过 `auipc+addi+jalr` **显式计算目标物理地址**后执行。

**XIP 窗口重叠问题**：SPI 窗口 `0x1C00_0000` 有别名 `0x1FE8_0000`，两者指向同一存储体。[RTL 实测] `docs/kb/platform-facts.md` §2.3
→ **早期引导代码不得依赖别名语义**；统一使用主窗口 `0x1C00_0000`。

**取指路径一致性**：XIP 直读 SPI，**无 cache 一致性协议**；取指命中 SPI 窗口时**必须绕过 I-Cache**，否则会对只读存储体产生缓存一致性问题。
→ 强度：**[旧项目转述]**（工程口径，非 RTL 显式事实）。**落地前需在核内取指路径上实测确认**，并写入 `rtl/pkg/*defs.vh` 的地址窗口常量。

### 2.3 阶段 B：拷入 DDR

**动作**：把后续镜像（OpenSBI / U-Boot / 内核 / DTB）从 SPI 或 NAND 读出，写入 DDR3。

**地址口径**：DDR3 位于 `0x0000_0000–0x07FF_FFFF`（128 MiB）。[RTL 实测] `docs/kb/platform-facts.md` §2.1

**DDR 内布局建议** [工程约定]：

| 用途 | 建议地址 | 大小 |
|---|---|---|
| 早期引导栈 / 暂存 | `0x0000_0000` 起向上 | 小量 |
| OpenSBI 运行地址 | `0x0100_0000` | ≤ 1 MiB |
| U-Boot 运行地址 | `0x0200_0000` | 数 MiB |
| Linux 内核 | `0x0400_0000` | ≤ 50 MiB 量级 |
| DTB | 内核之上 | |
| initramfs / rootfs | 高位 | |

- **注**：上表为**工程约定**，不是平台硬事实；最终地址必须在链接脚本与 DTS 中**统一**，且受 §4 分区大小约束。

### 2.4 阶段 C：跳 OpenSBI（M 模式）

- **入口参数（RISC-V 惯例）**[工程约定]：
  - `a0` = hart id；
  - `a1` = DTB 物理地址；
  - `a2` = 平台私有信息（可传 0）。
- OpenSBI 在 M 模式完成平台初始化后，通过 `mret` 进入 S 模式，跳转到 payload/next stage。
- **FW_JUMP vs FW_PAYLOAD 的选择**：见 `docs/porting/03-linux-opensbi.md` §4。

### 2.5 阶段 D：U-Boot（S 模式）

- U-Boot 在 S 模式运行，**不开 MMU**（物理地址直用）。
- 负责：外设驱动（NAND/MTD）、环境变量（`saveenv`）、`bootcmd` 自动启动（详见 `docs/porting/02-uboot.md`）。
- U-Boot 通过 **SBI 调用**获得 M 模式服务（定时器、IPI、重启等）。

### 2.6 阶段 E：Linux（S 模式，Sv32）

- Linux 开启 Sv32 页表：`satp.MODE = 1`。
- 从 DTB 获取内存与外设信息；从 NAND 读根文件系统。
- 详细方案见 `docs/porting/03-linux-opensbi.md`。

## 3. 镜像布局与 NAND 分区

### 3.1 分区口径 —— **项目自定义约定声明（重要）**

> ⚠️ **本节分区口径为项目自定义约定。**
>
> `nand-flash: 256K(env), 50M(kernel)ro, 1M(dtb), -(rootfs)`
>
> 该口径**来源为旧项目 `PROMPT.md` 的转述**（`rv32gc-cpu` 仓库 `master` 分支 `PROMPT.md:86`，本次仅作只读参考），**不是平台文档、不是 RTL 显式事实、也未经独立核实**。
> 标注强度：**[旧项目转述]**。
>
> **落地前必须完成的两件事**：
> 1. 在 U-Boot `mtdparts` 与 Linux DTS `partitions` 中**写成同一份定义**，两侧一致；
> 2. 按 §3.2 完成 **128 KiB NAND 块对齐核算**（本文已补做，见下表）。

### 3.2 与 128 KiB NAND 块的块对齐核算

**前提参数**（来自 NAND 芯片口径，强度 [旧项目转述]）：
- 块大小 = **128 KiB = 131072 B**；
- 总容量 = 128 MiB = 134217728 B；
- 总块数 = **1024**（= 134217728 / 131072，自洽）。

**核算表**（`%` 为取模运算）：

| 分区 | 大小 | 字节数 | `% 131072` | 是否整除 | 块数 | 起址（字节） | 起址 `% 131072` | 起址块对齐 |
|---|---|---|---|---|---|---|---|---|
| `nand-env` | 256 K | 262144 | **0** | ✅ 整除 | 2 | 0 | 0 | ✅ 是 |
| `kernel` | 50 M | 52428800 | **0** | ✅ 整除 | 400 | 262144 | 0 | ✅ 是 |
| `dtb` | 1 M | 1048576 | **0** | ✅ 整除 | 8 | 52690944 | 0 | ✅ 是 |
| `rootfs` | 剩余 | 80478208 | **0** | ✅ 整除 | 614 | 53739520 | 0 | ✅ 是 |
| **合计** | — | 134217728 | — | — | **1024** | — | — | ✅ |

**核算结论**：

1. **三个固定分区的大小全部能被 131072 整除**，**无需上取整**（这是选用 256 K / 50 M / 1 M 这组"整齐"数值的直接好处）。
   - 262144 / 131072 = 2（块）
   - 52428800 / 131072 = 400（块）
   - 1048576 / 131072 = 8（块）
2. **每段起址都自然块对齐**（起址 `% 131072 == 0`），因为各段大小均为块大小的整数倍、且首段起址为 0。
3. **`rootfs` 自动块对齐**：剩余 80478208 B，`80478208 % 131072 = 0`，共 614 块。
4. **块数合计 = 2 + 400 + 8 + 614 = 1024**，与总块数**精确吻合**，无浪费、无越界。

**关键起址（十六进制）**：

| 分区 | 起址 | 结束（不含） |
|---|---|---|
| `nand-env` | `0x0000_0000` | `0x0004_0000` |
| `kernel` | `0x0004_0000` | `0x0324_0000` |
| `dtb` | `0x0324_0000` | `0x0334_0000` |
| `rootfs` | `0x0334_0000` | `0x0800_0000` |

- 核算脚本（可复现）：
  ```sh
  python3 -c "
  blk=131072
  for n,s in [('env',256*1024),('kernel',50*1024*1024),('dtb',1*1024*1024)]:
      print(n, s, s%blk, s//blk)
  print('rootfs', 128*1024*1024-53739520, (128*1024*1024-53739520)%blk)
  "
  ```

### 3.3 分区用途

| 分区 | 用途 | 属性 |
|---|---|---|
| `nand-env` | U-Boot 环境变量区（`saveenv` 目标） | 可读写；**2 块冗余**（主+备）为 [工程约定] |
| `kernel` | Linux 内核镜像（+ 可能的 OpenSBI/U-Boot 镜像） | **只读**（`ro`） |
| `dtb` | 设备树 blob | 只读 |
| `rootfs` | 根文件系统（UBIFS 或镜像式） | 可读写 |

- **注意**：分区口径写的是 `50M(kernel)ro`，即 kernel 分区标记只读。**注意 U-Boot 的 `mtdparts` 语法里 `ro` 的语义**需在实现时确认（通常只影响 Linux MTD 侧的分区只读标志，U-Boot 侧仍可擦写）。[工程约定] / 待核实。

> **用户已定（2026-09-14）**：NAND 分区/几何的裁决口径 —— 以 chiplab RTL（`IP/APB_DEV/NAND/nand.v`、`apb_dev_top_with_nand.v`）与 la32r-Linux 驱动（`ls1a_nand.c`）的**实际实现为准**；工作口径 "块 128 KiB = 主区 64 页 × 2048 B，备用区 64 × 64 B 另行"；**不修改 chiplab NAND 模块**。本节分区表（`256K/50M/1M/-`）为项目自定义约定，块对齐仍按 128 KiB 核算。详见 `04-nand-driver.md` §1.2/§8。

### 3.4 与 SPI NOR 的分工

- SPI NOR = 16 MiB，存放 **PMON / 早期引导 / U-Boot**（DIP 插座）。[旧项目转述]
- NAND = 128 MiB，存放 **env / kernel / dtb / rootfs**（§3.1）。
- **边界**：SPI 负责"**从复位到 U-Boot 起来**"；NAND 负责"**U-Boot 之后的一切**"。

## 4. 时钟口径

- **上板运行频率 = 33 MHz**（`clk_pll_33.clk_out2`），CPU 与 uncore **同域**（`cpu_clk = uncore_clk`，AXI 无 CDC）。[RTL 实测] `docs/kb/platform-facts.md` §5
- 软件侧对应常量：**`FREQ = 32'd33000000`**（`config.h:33`）。[RTL 实测] `docs/kb/platform-facts.md` §5
- 该常量必须同步到：U-Boot 的 `CONFIG_SYS_CLK_FREQ` 类配置、Linux DTS 的 `timebase-frequency`、OpenSBI 的平台时钟。
- **[工程约定]** 三处的频率值必须**逐字一致**，且与 `config.h:33` 一致；任何一处漏改都会导致定时器/UART 波特率错乱。

## 6. 交付与自证要求

[工程约定] 每一层软件的移植**必须自证**：

1. **可复现命令** + **判定输出**（构建产物存在、启动日志关键行命中）；
2. **回归脚本"未捕获即失败"**（兜底文案不得含 `PASS`）；
3. 镜像切分**按 LMA**，并打印每段 LMA/VMA 对照；
4. 每阶段结束**停下等用户审阅**，不擅自进入下一阶段。
